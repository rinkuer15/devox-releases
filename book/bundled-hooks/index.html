Bundled Hooks — Quality Gates Out of the Box

In Chapter 9 you learned to write per-node hooks in YAML — static responses that intercept tool calls inside a single workflow node. Those are great for guardrails baked into a specific workflow.

Bundled hooks are different. They are shell scripts that run globally, on every AI session — not per-node, not per-workflow. They fire at the provider level: before every Bash command, after every file edit, at session end. You install them once and they run everywhere.

Devox ships 8 bundled hook scripts. This chapter explains what they do, how to install them, and how to customise or override them.

What Bundled Hooks Are

Section titled “What Bundled Hooks Are”

A bundled hook is a shell script registered with the AI provider’s native hook system:

  • Claude — hooks registered in .claude/settings.json via hooks: entries
  • Copilot — hooks registered in .devox/copilot-hooks.yaml
  • Codex / Pi — no native hook API; scripts are extracted to disk for manual integration

When you run devox hooks install, Devox:

  1. Extracts the 8 bundled scripts to ~/.devox/hooks/ (or .devox/hooks/ for project scope)
  2. Patches .claude/settings.json with the correct event + matcher entries
  3. Writes .devox/copilot-hooks.yaml with the equivalent Copilot config

After install, every Claude and Copilot session automatically runs the hooks — no workflow changes required.

The 8 Bundled Hooks

Section titled “The 8 Bundled Hooks”

Quality Gates

Section titled “Quality Gates”

pre-commit-quality-gate — Runs before every git commit
Scans the staged diff for console.log, debugger, and hardcoded secrets.
Exits 2 on critical findings (blocks the commit). Warns on minor issues.
Provider events: PreToolUse / Bash matcher

post-edit-typecheck — Runs after editing .ts or .tsx files
Immediately runs tsc --noEmit and surfaces type errors in-context.
Catches TypeScript mistakes before they compound.
Provider events: PostToolUse / Edit matcher

post-edit-lint — Runs after editing .ts, .js, .py, or .rs files
Runs ESLint, Ruff, or Clippy on the edited file.
Provider events: PostToolUse / Edit matcher*

Safety

Section titled “Safety”

dev-server-blocker — Runs before every Bash command
Detects bun dev, npm run dev, pnpm dev, yarn dev without & or tmux.
Blocks foreground dev server commands and suggests bun dev & instead.
Prevents the AI from hanging a session on a blocking process.
Provider events: PreToolUse / Bash matcher

Observability

Section titled “Observability”

pr-url-logger — Runs after gh pr create
Extracts the PR URL from the command output and appends it to .devox/state/prs.log.
Builds a persistent record of every PR created in this project.
Provider events: PostToolUse / Bash matcher

session-summary — Runs at session end
Persists a JSONL summary to .devox/state/session-history.jsonl.
Feeds into continuous learning and helps reconstruct what happened in past sessions.
Provider events: Stop / SessionEnd

instinct-extractor — Runs at session end
Evaluates the session for extractable patterns and appends them to .devox/state/instincts.json.
Over time this file accumulates project-specific knowledge that can be reviewed and promoted to rules.
Provider events: Stop / SessionEnd

Ergonomics

Section titled “Ergonomics”

context-compact-reminder — Runs before Edit or Write tools
Counts tool calls. Around 50 calls, injects a suggestion to run /compact to avoid context overflow.
Provider events: PreToolUse / Edit|Write matcher

Installing

Section titled “Installing”

devox hooks install does three things:

  1. Writes scripts to ~/.devox/hooks/ (global) or <cwd>/.devox/hooks/ (project)
  2. Patches .claude/settings.json with hook registrations
  3. Writes .devox/copilot-hooks.yaml with Copilot hook config
