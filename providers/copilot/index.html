GitHub Copilot

Connect Devox to GitHub Copilot via the @github/copilot-sdk — no separate binary install, no extra API cost if you already have a Copilot subscription. Supports MCP servers, hooks, skills, and inline sub-agents.

Provider ID: copilot · Built-in: ✅ · SDK: @github/copilot-sdk

Prerequisites

Section titled “Prerequisites”
  • Devox installed (see Getting Started)
  • An active GitHub Copilot subscription (Individual, Business, or Enterprise)
  • The GitHub CLI (gh) installed (recommended)

Authentication

Section titled “Authentication”

Pick one of the two options below. Set the chosen variable(s) in ~/.devox/.env.

Option 1 — Stored gh CLI credentials (recommended)

Section titled “Option 1 — Stored gh CLI credentials (recommended)”

The zero-token approach — no env var needed. Devox resolves the token automatically via gh auth token at runtime.

Option 2 — Explicit token (CI/CD, no gh CLI, or Windows fallback)

Section titled “Option 2 — Explicit token (CI/CD, no gh CLI, or Windows fallback)”

Set COPILOT_GITHUB_TOKEN to a GitHub OAuth user token (gho_) or GitHub App user token (ghu_) with the Copilot scope:

Getting a gho_ token when you have gh installed:

note[Token compatibility] GH_TOKEN and GITHUB_TOKEN are not used for Copilot — they are for the GitHub forge adapter only. Devox automatically strips them from the Copilot subprocess environment to prevent interference.

Classic Personal Access Tokens (ghp_ / github_pat_) are rejected by the Copilot API. Use gho_ or ghu_ tokens only.

Configuration Options

Section titled “Configuration Options”

enableConfigDiscovery: When true, the SDK automatically discovers .mcp.json and skill directories from the session working directory. Default: false.

agentPaths: Extra directories scanned for agent .md files, appended after the standard global and project locations. Supports ~ expansion.

note[Prefer the unified effort field in workflows] reasoningEffort here is Copilot’s config-level default. In workflow YAML (workflow- or node-level), use the unified effort: field instead — it works the same way across Claude, Codex, Copilot, and Pi. See Workflow Options below and Reasoning Effort.

Skill Locations

Section titled “Skill Locations”

Copilot scans these directories for skills (all additive — project and global):

PathScope
<cwd>/.agents/skills/<name>/SKILL.mdProject
<cwd>/.claude/skills/<name>/SKILL.mdProject
~/.agents/skills/<name>/SKILL.mdGlobal
~/.claude/skills/<name>/SKILL.mdGlobal

Agent Locations

Section titled “Agent Locations”

Copilot loads agent definition files from these directories (lowest → highest priority):

PathScopeFormat
~/.agents/agents/Global (legacy Devox convention).md
~/.claude/agents/Global (Claude convention).md
~/.copilot/agents/Global (official GitHub Copilot CLI).agent.md
<cwd>/.agents/agents/Project (legacy Devox convention).md
<cwd>/.claude/agents/Project (Claude convention).md
<cwd>/.github/agents/Project (official GitHub Copilot).agent.md

Recommended locations:

  • Use .claude/agents/ for portability — works with Claude SDK natively and all other providers (Copilot, Codex, Pi) via Devox
  • Use .github/agents/ (project) or ~/.copilot/agents/ (global) for Copilot-native agents that need tools: or mcp-servers: in the frontmatter

Copilot-native format (.agent.md files) supports additional frontmatter:

The Web UI Agents tab lets you create agents in any of these locations without writing YAML manually.

Hooks

Section titled “Hooks”

Copilot supports the same hook format as Claude — define session-level hooks in config, or per-node hooks in workflow YAML:

Supported hook events: PreToolUse, PostToolUse, SessionEnd, UserPromptSubmitted

Hook types: text (inject additionalContext) or command (run shell script)

Actions (PreToolUse only): deny, allow, deny-on-failure

Scripts receive Claude-compatible JSON on stdin:

  • PreToolUse: { session_id, tool_name, tool_input: { ...toolArgs } }
  • PostToolUse: { session_id, tool_name, tool_input, tool_response }
  • SessionEnd: { session_id }

Troubleshooting

Section titled “Troubleshooting”
ErrorFix
”Session was not created with authentication info”Run gh auth refresh --scopes copilot, restart the server. Or set COPILOT_GITHUB_TOKEN explicitly.
”Personal Access Token does not have Copilot Requests permission”You used a ghp_ PAT. Run gh auth token --hostname github.com to get a gho_ token.
”Authorization error / run /login”Your token expired. Run gh auth refresh --scopes copilot and restart.
Connection times outCheck your subscription is active at github.com/settings/copilot.
