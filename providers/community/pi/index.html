Pi (Community Provider)

Note

Pi is a community provider — contributed and maintained by the community (@mariozechner/pi-coding-agent). It is registered as builtIn: false.

Connect Devox to Pi for access to ~20 LLM backends through a single provider — Anthropic (Claude), OpenAI (GPT), Google (Gemini), Groq (Llama), Mistral, Cerebras, xAI, OpenRouter, Hugging Face, and more — all under provider: pi.

Provider ID: pi · Built-in: ❌ (community) · SDK: @mariozechner/pi-coding-agent

Prerequisites

Section titled “Prerequisites”
  • Devox installed (see Getting Started)
  • API key(s) for your chosen backend(s), or an OAuth subscription via pi /login

Install

Section titled “Install”

Pi is bundled as a dependency of @devox/providers — no separate install needed. It is available immediately after bun install.

Authentication

Section titled “Authentication”

Pi supports both OAuth subscriptions and direct API keys. Devox’s adapter reads credentials from ~/.pi/agent/auth.json (written by pi /login) and from env vars — env vars take priority per-request, so codebase-scoped key overrides work.

Additional backends (Azure, Bedrock, Vertex, etc.) — file an issue if you need them wired.

Configuration Options

Section titled “Configuration Options”

maxConcurrent: Pi has no built-in SDK-level throttling. For large parallel workflow batches (10+ concurrent nodes), set this to your Pi API tier’s concurrency limit to avoid cascade rate-limit failures.

Pi Extensions

Section titled “Pi Extensions”

Pi supports a community extension system for tools and lifecycle hooks. Extensions live in ~/.pi/agent/extensions/ (global) and .pi/extensions/ (project). They are loaded before session_start.

Control extension loading via config:

Workflow Options

Section titled “Workflow Options”
OptionValuesDescription
providerpiUse the Pi community provider for this node
model<provider>/<modelId>Required — e.g., google/gemini-2.5-pro
effortminimal | low | medium | high | maxThinking level (max maps to Pi’s xhigh)
skills[name, ...]Skill directories with SKILL.md
allowed_tools[read, bash, edit, write, grep, find, ls]Restrict Pi’s built-in coding tools
denied_tools[bash, ...]Exclude specific tools from Pi’s default set
systemPromptstringOverride the system prompt for this node
output_formatjsonStructured JSON (best-effort via prompt + JSON extraction)

Tip

Pi supports effortControl and thinkingControl via the effort field. Use effort: max for maximum reasoning (Pi translates to xhigh internally). The Claude-specific thinking: { type: enabled, budget_tokens: N } object form is not supported by Pi — use effort instead.

Troubleshooting

Section titled “Troubleshooting”
SymptomLikely causeFix
Invalid API keyMissing env var for chosen backendAdd the matching key to ~/.devox/.env (e.g., GEMINI_API_KEY=...)
Rate limit errors in parallel batchesToo many concurrent Pi callsSet maxConcurrent in config to match your API tier
Model not foundWrong <provider>/<model> formatCheck available models via pi models in the Pi TUI
Extension errors at session startExtension not installed or path wrongCheck ~/.pi/agent/extensions/ and project .pi/extensions/
