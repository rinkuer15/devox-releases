Global Workflows, Commands, and Scripts

Devox supports three types of home-scoped (“global”) resources that are automatically available in every project — no per-repo setup required.

ResourcePathPurpose
Workflows~/.devox/workflows/Multi-step AI pipelines available in every repo
Commands~/.devox/commands/Reusable AI command files available in every repo
Scripts~/.devox/scripts/TypeScript/Python helpers for script: nodes in any repo

Load Priority

Section titled “Load Priority”

Resources are merged in this order (repo always wins):

  1. Bundled defaults (lowest priority)
  2. Global — ~/.devox/workflows/, ~/.devox/commands/, ~/.devox/scripts/ (override bundled by filename)
  3. Repo-specific — .devox/workflows/, .devox/commands/, .devox/scripts/ (override global by filename)

Same-filename collision at any tier: the higher-priority source silently wins. Global commands have source: 'global' in /api/commands responses.

Subfolders are supported one level deep (e.g. ~/.devox/workflows/triage/foo.yaml resolves as foo). Deeper nesting is ignored silently.

Workflow/Command/Script Not Found

Section titled “Workflow/Command/Script Not Found”

  1. Check the path — The correct directories are ~/.devox/workflows/, ~/.devox/commands/, and ~/.devox/scripts/ (single .devox, directly under home).

  2. Check file extension — Workflow files must end in .yaml or .yml; command files must end in .md; scripts must end in .ts, .js, or .py.

  3. Check YAML validity — A syntax error causes the workflow to appear in the errors list. Run:

  4. Check for name conflicts — A repo-specific workflow/command/script with the same filename overrides the global one when you are inside that repo.

  5. Check DEVOX_HOME — If you set DEVOX_HOME, all paths are relative to that directory (e.g. $DEVOX_HOME/workflows/).
