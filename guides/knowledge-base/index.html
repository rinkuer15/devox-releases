Knowledge Base

Devox includes a built-in Knowledge Base — a RAG (Retrieval-Augmented Generation) system that lets you index documentation, web pages, uploaded files, and code folders into a vector store, then expose that knowledge to AI agents during workflow execution via MCP.

Devox knowledge pipeline built with hybrid search strategy (1.3× BM25 boost, 0.15 similarity threshold).

What it gives you

Section titled “What it gives you”
Without Knowledge BaseWith Knowledge Base
Agent only knows code in the current repoAgent can reference any docs you’ve indexed
You paste context manually into promptsAgent searches automatically via search_knowledge MCP tool
External docs go stale in the agent’s contextRe-index in one click; agents always get fresh chunks

Step 1 — Choose a vector store

Section titled “Step 1 — Choose a vector store”

Supabase pgvector (default, recommended)

Section titled “Supabase pgvector (default, recommended)”

Supabase gives you PostgreSQL + pgvector in one hosted service, free tier available.

  1. Create a project at supabase.com
  2. Open the SQL Editor in your project dashboard
  3. Run the schema from packages/knowledge/supabase/schema.sql:

The full file includes two PL/pgSQL functions (match_devox_knowledge_chunks and keyword_search_devox_knowledge_chunks) that the Supabase provider calls for vector and keyword search respectively.

  1. Copy your Project URL and anon key from Project Settings → API.

Qdrant

Section titled “Qdrant”

Qdrant is an open-source vector database you can run locally or on Qdrant Cloud.

No schema setup needed — Devox creates the collection automatically on first ingest.

ChromaDB

Section titled “ChromaDB”

No schema setup needed.

Step 3 — Add knowledge sources

Section titled “Step 3 — Add knowledge sources”

Navigate to the Knowledge tab in the sidebar.

URL

Section titled “URL”

Crawls a web page, strips HTML, extracts clean text.

  1. Click + Add URL
  2. Enter the URL and a display name
  3. Click Add — ingest starts immediately; progress streams in real time

File upload

Section titled “File upload”

Accepts PDF (.pdf), Word (.docx), Markdown (.md), and plain text (.txt).

  1. Click Upload File
  2. Select your file
  3. Click Upload — file is parsed, chunked, embedded, and indexed

Code folder

Section titled “Code folder”

Recursively indexes every source file in a directory, respecting common ignore patterns (.git, node_modules, dist, etc.).

  1. Click Add Code Folder
  2. Enter the absolute path to the folder on the server
  3. Choose file extensions to include (default: ts, js, py, go, rs, md)
  4. Click Add

Chunking strategy

Section titled “Chunking strategy”

Devox uses a context-aware chunker (packages/knowledge/src/chunker.ts) via smart_chunk_text():

  1. Code blocks — ``` boundaries are preserved as complete units
  2. Paragraph boundaries — \n\n splits are preferred
  3. Sentence boundaries — . splits as fallback
  4. Hard split — only when no natural boundary exists within the chunk window

Default chunk size: 5000 characters (configurable in Settings → Knowledge).

Hybrid search

Section titled “Hybrid search”

When useHybridSearch: true (default), Devox runs two searches in parallel:

  1. Vector similarity — cosine distance via embedding
  2. Keyword (BM25-style) — PostgreSQL full-text search using ts_rank

Results are merged with a 1.3× boost for results that appear in both lists. Chunks below a 0.15 similarity threshold are filtered out.

This is the Devox HybridSearchStrategy.

Troubleshooting

Section titled “Troubleshooting”

”No results found” after indexing

Section titled “”No results found” after indexing”
  • Check that your embedding model API key is set correctly
  • Verify the similarity threshold (default 0.15) isn’t too high for your content
  • For Supabase: confirm the match_devox_knowledge_chunks RPC function was created

Supabase dimension error

Section titled “Supabase dimension error”

Your vector(N) dimension in the table doesn’t match the embedding model output. Drop and recreate the table with the correct dimension and re-ingest all sources.

ChromaDB “connection refused”

Section titled “ChromaDB “connection refused””

Ensure ChromaDB is running: chroma run --host localhost --port 8000

PDF extraction empty

Section titled “PDF extraction empty”

Some PDFs are image-only (scanned). Devox’s pdf-parse extracts text layers only. Use a tool like pdftotext to pre-process scanned PDFs before upload.
