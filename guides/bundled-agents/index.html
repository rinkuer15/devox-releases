Bundled Agents

Devox ships 29 specialised AI agent personas inside the binary. They are split into two categories:

  • Core agents (15) — automatically deployed by devox doctor. These are the agents actually used by bundled default workflows. They load into every Claude session context window.
  • Curated agents (14) — available on demand. Deploy only the ones you need to keep token overhead minimal.

You can manage agents from the Web UI Catalog tab or the CLI.

Quick Start

Section titled “Quick Start”

Why Two Categories?

Section titled “Why Two Categories?”

Every .md file in ~/.claude/agents/ is injected into Claude’s context window at session start. With 29 agents that adds up fast. Devox ships only the 15 agents that its bundled workflows actually invoke as core — reducing context overhead by ~50% vs. deploying everything. The other 14 curated agents are ready to deploy when you need them.

Discovery Hierarchy

Section titled “Discovery Hierarchy”

Three-layer merge, lowest → highest precedence. Same-named file at a higher scope wins.

LayerLocationsScope
bundledInside Devox binaryAll users, all repos
global~/.devox/agents/, ~/.agents/agents/, ~/.claude/agents/, ~/.copilot/agents/Your machine, all repos
project<cwd>/.devox/agents/, <cwd>/.agents/agents/, <cwd>/.claude/agents/, <cwd>/.github/agents/This repo only

Deploy target: devox agents deploy writes to ~/.claude/agents/ (global) or <cwd>/.claude/agents/ (project). Both paths are in every provider’s auto-discovery chain.

  • rulecheck-agent — isolation: worktree, permissionMode: acceptEdits, hooks, maxTurns: 500

Managing Agents — Web UI

Section titled “Managing Agents — Web UI”

The Web UI Agents tab has three sections:

  • Global — agents in ~/.claude/agents/ available across all projects
  • Project — agents scoped to the selected project’s .claude/agents/
  • Catalog — full list of all 29 bundled agents (core + curated) with deploy/undeploy buttons

Using the Catalog tab

Section titled “Using the Catalog tab”
  1. Navigate to Agents → Catalog in the sidebar
  2. Core agents (15) are shown at the top — these should always be deployed (auto-done by doctor)
  3. Curated agents (14) can be deployed individually with the Deploy button
  4. Click View on any agent to preview its full content before deploying
  5. Undeploy removes an agent from ~/.claude/agents/, freeing context space

Creating custom agents

Section titled “Creating custom agents”
  1. Click New Global Agent or New Project Agent in the Global/Project tabs
  2. Fill in Name (slug format: my-reviewer), Description, and Prompt / Instructions
  3. Choose a Save location:
    • .claude/agents/ — works with Claude and Copilot (recommended for portability)
    • .github/agents/ or ~/.copilot/agents/ — Copilot-native format (.agent.md extension)
  4. Optionally expand Advanced to set tool restrictions and MCP servers
  5. Click Save Agent

Edit / Delete

Section titled “Edit / Delete”

Click the pencil icon on any agent card to edit. Unknown frontmatter fields (e.g. model, hooks) are preserved on save. Click the trash icon to delete. Bundled read-only agents cannot be deleted this way — use Undeploy from the Catalog tab instead.

Tools section

Section titled “Tools section”

  • Custom tools — type a tool name and press Enter or Add (useful for MCP tool names like mcp__linear__create_issue)
  • Leave all tools unchecked = no restriction (all tools allowed)

Adding a New Core Agent (for Devox contributors)

Section titled “Adding a New Core Agent (for Devox contributors)”

To ship a new agent as part of the auto-deployed core set:

  1. Add the .md file to .claude/agents/ in the repo
  2. Add the agent name to "core" in packages/cli/src/bundled-agent-categories.json
  3. Add the same name to CORE_AGENTS in packages/server/src/routes/api.agents.ts
  4. Run bun run generate:bundled to refresh the binary bundle
  5. Existing users will get the new agent auto-deployed on their next devox doctor run
